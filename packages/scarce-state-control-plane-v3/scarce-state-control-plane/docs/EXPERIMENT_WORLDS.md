# WORLD_SELECT and experiment classes

## Core question

> Where can reality answer this hypothesis fastest, cheapest and with sufficient evidence quality?

A software build is not automatically the next step. The next step is the smallest intervention that can move the belief state.

## Four experiment classes

### A — Truth
Tests a causal prediction against external reality. Primary v3 world: paper trading.

Required discipline:
1. freeze thesis before outcome;
2. freeze horizon and falsifier;
3. freeze benchmark;
4. resolve from independent external data;
5. preserve failures.

### B — Demand
Tests voluntary usage. ChatGPT apps are especially useful because they are cheap disposable surfaces. Usage validates workflow demand; it does not validate a durable moat.

### C — Economic
Tests money/tradeoff. Etsy/marketplace experiments are useful because real purchases/sales generate harder feedback than usage.

### D — Scarce state
Tests actual acquisition of durable state: delegated authority, customer relationship, proprietary transaction outcome, physical observation, network participant, etc.

## Selection heuristic

```text
ExperimentValue =
    information_gain × feedback_quality × economic_relevance
    -------------------------------------------------------
    money_factor × time_factor × human_factor × irreversibility
```

The score only orders experiments. It is not truth and never bypasses UNDERENGINEER/QP.

## Simulation boundary

Internal simulation/backtesting can:
- rank alternatives;
- test validator logic;
- stress assumptions;
- estimate information value;
- cheaply kill obviously weak branches.

It cannot prove:
- users want something;
- customers will pay;
- a marketplace clears;
- a business granted permission;
- scarce state was acquired.
