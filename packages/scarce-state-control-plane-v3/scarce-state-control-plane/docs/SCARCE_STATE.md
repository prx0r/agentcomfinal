# Scarce-state thesis

## Strategic invariant

```text
Can OpenAI/platform vendors destroy this merely by writing more software?
```

If yes, the capability is normally internal infrastructure rather than the long-term business.

If no, name exactly what survives. Typical classes:

- delegated authority / permission;
- proprietary live state or outcome history;
- customers and relationships;
- marketplace liquidity / network state;
- trusted reputation;
- physical inventory/execution/state;
- regulated authority/licensing;
- exclusive supply/access;
- lower physical cost structure.

## Asset representation

Every scarce asset records:

```text
controller
our right
unit of controlled state
acquisition event
decay event
exclusivity
externality (cannot be synthesized by cognition)
feedback/trajectory compounding
network effects
trust/authority
AI moat beta
platform capture
public replicability
synthetic substitutability
```

Declared assets start at stock `0`. A thesis file does not create an asset. The ledger can only move from verified acquisition/decay receipts.

## Two AI betas

`product AI beta`: does better AI improve the product?

`moat AI beta`: does better AI make our scarce asset relatively more valuable?

A plugin compiler can have positive product beta and negative moat beta. Delegated authority or private outcome data can have positive moat beta as agents get more capable.
