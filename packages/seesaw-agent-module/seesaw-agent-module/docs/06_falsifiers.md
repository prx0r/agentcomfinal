# 6. Falsifiers and Research Program

Seesaw should be empirically wrong-able.

## Hypothesis 1
Projects attached to external consequential state retain value better than pure software wrappers as frontier capability improves.

**Falsifier:** wrapper-only products retain comparable margins/retention after direct platform feature entry.

## Hypothesis 2
Positive-AI-beta assets outperform model-specific implementation advantages.

**Falsifier:** improved foundation models systematically reduce demand for authority/data/action assets rather than increasing it.

## Hypothesis 3
State-action-outcome trajectories create durable improvement/defensibility.

**Falsifier:** trajectory ownership does not improve prediction, operation, pricing, retention, or model performance over publicly reproducible data.

## Hypothesis 4
Open-source/API reuse is superior for commodity layers.

**Falsifier:** integration/maintenance cost repeatedly exceeds bespoke implementation cost in the relevant project class.

## Hypothesis 5
Plugin/interface layers commoditize faster than underlying external capability.

**Falsifier:** platform fragmentation or proprietary interface rents persist for long periods and become stronger moats than state ownership.

## Hypothesis 6
Network/trust/authority remain scarce.

**Falsifier:** agents can cheaply recreate equivalent trust, liquidity, legal rights, and institutional access with minimal historical accumulation.

## Historical/prospective logging

Every Seesaw decision should store:

```text
date
event
pre-event project score
decision
reason
falsifier
6m outcome
12m outcome
24m outcome
```

Then evaluate calibration.

The objective is not to preserve the framework.

The objective is to make it predictively useful enough to allocate finite engineering time better than intuition alone.
